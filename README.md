# Доставка еды: REST API

Учебное серверное приложение на Node.js и Express. Автор: Жамшитов Дильмурат Шакирович, ИИ-402, ABU.

## Запуск

Требуется Node.js 22 или новее. В папке проекта:

```powershell
npm ci
npm start
```

Адрес: http://127.0.0.1:3010. Сервер доступен только на этом компьютере.
Для остановки нажать Ctrl+C. Для автоматического перезапуска при изменении кода: `npm run dev`.

## Маршруты

| Метод | URL | Назначение | Успех |
|---|---|---|---|
| GET | / | Информация о приложении | 200 |
| GET | /api/health | Проверка работы | 200 |
| GET | /api/dishes | Список блюд | 200 |
| GET | /api/dishes/:id | Блюдо по id | 200 |
| POST | /api/dishes | Добавление | 201 |
| PUT | /api/dishes/:id | Полная замена полей блюда | 200 |
| DELETE | /api/dishes/:id | Удаление | 204 |

Фильтры списка: `category=Пицца`, `search=бургер`, `available=true`. Можно сочетать.
POST и PUT требуют заголовок `Content-Type: application/json` и тело:

```json
{
  "name": "Сырные палочки",
  "category": "Закуски",
  "price": 1200,
  "available": true
}
```

Цены указаны в тенге. Поля name, category и price обязательны. Если available не указан, принимается true.
Ошибки: 400 - неверные данные; 404 - блюдо или маршрут не найдены; 413 - JSON больше 32 КБ; 415 - неверный Content-Type; 500 - внутренняя ошибка.
Стек ошибок клиенту не передаётся.

## Структура и middleware

- `src/server.js` запускает HTTP-сервер.
- `src/app.js` соединяет middleware и маршруты.
- `src/routes/dishes.js` содержит Router и обработчики CRUD.
- `src/middleware.js` содержит журнал запросов, проверку данных и обработчик ошибок.
- `src/store.js` читает и сохраняет данные в `data/dishes.json`.
- `src/data/seed.js` задаёт 20 начальных блюд.
- `test/api.test.js` проверяет API на отдельном временном наборе данных.
- `postman/Food_Delivery.postman_collection.json` содержит запросы и проверки Postman.

Запрос проходит через журнал, JSON-парсер и подходящий маршрут. Для POST/PUT вызывается проверка полей. При ошибке `next(err)` передаёт управление обработчику с четырьмя параметрами `(err, req, res, next)`. Неизвестный маршрут получает JSON с кодом 404. Каждый ответ содержит X-Request-Id.

При первом запуске используются 20 блюд. Первое изменение создаёт файл данных. Изменения сохраняются после перезапуска. Это небольшой учебный сервер: синхронная работа с JSON подходит для демонстрации, но для многопроцессного приложения нужна база данных. Авторизация и оплата в задание не включены.

## Проверка в Postman

1. Запустить сервер.
2. Нажать Import и выбрать файл из папки `postman`.
3. Открыть импортированную коллекцию. Переменная `baseUrl` уже содержит http://127.0.0.1:3010.
4. Выполнить Run collection в исходном порядке: проверка сервера, список, фильтр, создание, чтение, изменение, удаление и ошибочные запросы.
5. Коллекция сохраняет id созданного блюда в `dishId`. Не запускать несколько её копий одновременно.

Созданное тестовое блюдо удаляется в конце основного сценария. При прерывании запуска оно может остаться в меню.
Для автоматической проверки Node.js выполнить `npm test`. Эти тесты не меняют рабочее меню.

## Коротко для защиты

Node.js запускает JavaScript на сервере. Express помогает создавать маршруты и подключать middleware.
Маршрут выбирается по HTTP-методу и URL. Например, GET /api/dishes читает меню, а POST по этому же адресу создаёт запись.
Middleware выполняет общие действия: разбирает JSON, записывает запрос и проверяет данные. Вызов next() продолжает обработку.
Разделение на файлы позволяет отдельно менять запуск, маршруты, проверку и хранение.
В Postman нужно показать успешный GET, POST с кодом 201, PUT, DELETE с кодом 204 и ошибочные запросы 400/404.
